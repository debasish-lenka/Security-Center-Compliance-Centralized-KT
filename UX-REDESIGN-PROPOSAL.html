Security Center — UX Redesign Proposal

Addressing Dashboard/Assignments overlap, Global Search gaps, and Navigation hierarchy issues

P1 — Critical P2 — High P3 — Medium

Executive Summary

Problem 1: Dashboard ≠ Assignments

Both pages show project cards, metrics, and activity feeds. Users can't distinguish "strategic overview" from "my daily work".

Problem 2: Global Search is Local

Header search only filters Documents. No cross-module results (projects, KT reports, compliance, users).

Problem 3: Flat Navigation

13 top-level items with no grouping. Admin items mixed with daily tools. No workspace concept.

1 Dashboard Separation Design

Design Principle: "Strategy vs. Execution"

Dashboard = Leadership view (health, trends, risks). My Assignments = Operator view (tasks, due dates, blockers).

Security Center Dashboard (P1)

Audience: Managers, CISO, Stakeholders | Cadence: Daily/Weekly review

Portfolio Health Score — Aggregate compliance, risk, delivery metrics
Risk Heatmap — Projects by risk level + trend arrows
Compliance Posture — Framework scores (ISO 27001, NIST, SOC 2) with drift indicators
Resource Allocation — Team capacity vs. committed work
Executive Alerts — Only critical/escalated items requiring decision
Trend Sparklines — 30/60/90-day views for key KPIs
Removed: Project cards, My tasks, Document lists, KT report lists

My Assignments Workspace (P1)

Audience: Analysts, Auditors, Contributors | Cadence: Hourly/Daily

My Task Board — Kanban: To Do / In Progress / Blocked / Done (filterable by project)
Due This Week — Sorted by urgency, with SLA countdown
Blockers & Dependencies — Items waiting on others, with @mention actions
KT Reports Due — My projects' reporting cadence with quick-submit
Recent Activity (Mine) — My comments, approvals, uploads
Quick Actions — Create task, Log time, Request review
Removed: Portfolio metrics, Compliance scores, Team workload charts

3 Updated Navigation Hierarchy (P1)

Design Principle: "Workspaces + Modules"

Group by user intent (Workspaces) and domain (Modules). Collapsible sections. Admin separated.

WORKSPACES

MODULES
Projects Documents KT Reports Compliance People
Administration

Key Changes

  • • Workspaces (Dashboard, My Assignments) — intent-based, top-level
  • • Modules (Projects, Documents, KT Reports, Compliance, People) — domain-based
  • • Administration — collapsible, only visible to Admin/Super Admin roles
  • • Removed: "All Projects" (merged into Projects module), "My Assignments" duplicate entry
  • • Search moved to header (global), not a nav item

Sequencing Recommendation

  1. Sprint 1: Navigation restructure (P1) + Header search wiring (P1) — enables discoverability
  2. Sprint 2: Dashboard/Assignments content split (P1) — core UX fix
  3. Sprint 3: Global Search results page (P1) — unified findability
  4. Sprint 4: Task Board in Assignments (P2) — daily workflow
  5. Sprint 5+: P2/P3 enhancements per feedback

6 Technical Considerations

API Changes Required

  • New GET /v1/search endpoint — unified search across modules
  • Add assignee=me filter to Projects, Tasks, KT Reports APIs
  • Dashboard metrics endpoint — aggregate portfolio health
  • Assignments endpoint — user-scoped tasks + due dates + blockers

Frontend Architecture

  • New routes: /dashboard, /assignments, /search
  • React Query keys: ['dashboard'], ['assignments'], ['search', query]
  • Sidebar: dynamic config from navigation.config.ts (role-aware)
  • Search: debounced input → navigate to /search?q=...

Migration Strategy

  • Keep / → redirect to /dashboard
  • Move current /assignments content to new /assignments
  • Deprecate old /dashboard component after validation
  • Feature flag NEW_NAV for gradual rollout

Accessibility

  • Search modal: trap focus, ESC to close, ARIA labels
  • Kanban: keyboard drag-drop (Space to pick, arrows to move, Enter to drop)
  • Sidebar: collapsible with ARIA-expanded, keyboard navigation
  • Color contrast: all badges meet WCAG AA
